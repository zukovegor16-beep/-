# Спецификация Excel-реестра (один файл на все аккаунты)

## Назначение

Файл **accounts.xlsx** — единственный источник настроек аккаунтов. Программа при **Старт** читает его, берёт видео из указанных папок и публикует **не больше `videos_per_run` роликов на аккаунт за один запуск**. Подпись для каждого ролика — **случайный** вариант из ячейки `caption_variants` в той же строке.

Путь к файлу задаётся в `config/settings.yaml`:

```yaml
excel:
  registry_path: "./config/accounts.xlsx"
  sheet_accounts: "Аккаунты"
  caption_delimiter: "|||"
```

## Лист «Аккаунты»

| Колонка | Тип | Описание |
|---------|-----|----------|
| account_no | число/текст | Уникальный номер аккаунта |
| account_name | текст | Отображаемое имя (отчёт) |
| video_folder | путь | Папка с `.mp4` / `.mov` |
| dolphin_profile_id | текст | ID профиля Dolphin Anty |
| videos_per_run | целое | Сколько видео выложить **за один Старт** для этой строки |
| caption_variants | текст | Варианты подписей через разделитель `|||` |
| active | да/нет | Участвует в прогоне |

Колонки **`status`** (можно назвать `last_run_status` или `статус`), `last_run_error`, `last_run_at` программа обновляет после прогона.

### Значения `status` (русский текст)

| Статус | Смысл |
|--------|--------|
| опубликовано | Ролик успешно выложен в TikTok |
| нет публикации | Upload/confirm не прошли |
| нет входа | В профиле Dolphin нет сессии TikTok |
| капча | Требуется ручная проверка |
| лимит TikTok | Слишком частые посты |
| тест без публикации | Режим `dry_run` |
| уже опубликовано | Файл был в ledger, повтор не делался |
| нет видео | В папке нет файлов в очереди |
| частично опубликовано (k/n) | Не все слоты `videos_per_run` успешны |

Полный список кодов — [`STATUS_MATRIX.ru.md`](STATUS_MATRIX.ru.md).

## Случайная подпись

Для каждой публикации:

1. Разбить `caption_variants` по `|||`.
2. Убрать пустые варианты.
3. Выбрать один вариант равновероятно (`secrets.SystemRandom`).
4. Записать использованный текст в отчёт (`caption_used`).

Если после разбора список пуст — ошибка «нет вариантов подписи», ролик не публикуется.

## Видео

- Берутся только из `video_folder` (корень папки).
- Подпапка `posted/` не сканируется (если включён перенос после успеха).
- Порядок: по дате изменения файла (настройка в `settings.yaml`).

## Один запуск «Старт»

- Для каждого активного аккаунта планируется до `videos_per_run` публикаций.
- **Порядок (зафиксировано): sequential** — как строки в таблице сверху вниз: сначала все **N** роликов с **первого** активного аккаунта, затем все **N** со **второго**, и так далее до конца листа. Round-robin не используем.
- Пример: acc1 (N=2), acc2 (N=1), acc3 (N=2) → публикации: acc1, acc1, acc2, acc3, acc3.
- Итог прогона: лист **Log** (опционально) + файл `data/reports/report_<run_id>.xlsx` с колонками: account_no, file, caption_used, status, error, started_at, finished_at.

## После успешной публикации (зафиксировано: вариант A)

При статусе **ok** файл **перемещается** из `video_folder` в **`video_folder/posted/`** (подпапка создаётся при необходимости). Повторный «Старт» не подхватывает файлы из `posted/`.

## Работа с открытым Excel

Перед **Старт** лучше закрыть `accounts.xlsx` в Microsoft Excel, иначе запись статусов в тот же файл может не выполниться. Отчёт за прогон сохраняется всегда.
