# 20 фильтров по работоспособности (1а + 1б)

Не про закон, мораль, «пиратка плохая», «малварь плохая».
Только: **это рабочий объект или пустая/сгенерированная оболочка**.

URL по одному не открывались. Это эвристики по строке. Ответь номерами, например: `1 3 8 11 13 17`.

Сейчас в сырье: **1а = 301 728** доменов, **1б = 7 722** репо/имён.

## 1а — сайты (кино / торрент / казино)

### 1. Только корень, без субдоменного фарша
Оставить `lordfilm.art`, выкинуть `0-00.lordfilm0.biz`, `01.hdrezka.info`.
Сейчас с одной точкой (похоже на корень): **213 128**. С двумя и глубже: **88 600**.
Зачем: куча `0-100.` — генератор зеркал, не отдельный сервис.

### 2. Схлопнуть зеркала до одного регистрируемого домена
`0.piratbit.fun` + `007.piratbit.fun` + `010223.piratbit.fun` → одна строка `piratbit.fun`.
Уникальных «корней» примерно **226 272**. Ферм с ≥50 алиасами: **186**.
Зачем: иначе 1а читается как 300к почти одинаковых lordfilm.

### 3. Убрать хосты, которые начинаются с цифры
`010123.lordfilm2025.name`, `0-admiralx.icu`. Таких **54 961**.
Зачем: типичный автогенератор. Корень без цифры чаще и есть тот самый рабочий сайт.

### 4. Отделить одноразовые TLD от устойчивых
Одноразовые: `.cfd .buzz .lol .lat .icu .qpon .vu .fun .life` (только `.top` уже **70 180**).
Устойчивее: `.ru .com .org .net` (`.ru` **37 383**, `.com` **22 541**).
Зачем: не «плохое/хорошее», а «этот адрес завтра сменится» vs «этот держат дольше».

### 5. Убрать домены с годом в имени
`lordfilm2025`, `lordfilms-2022`. Таких **5 834**.
Зачем: сезонные прокладки. После сезона часто дохнут, хотя бренд тот же.

### 6. Убрать «прочерковый фарш» (3+ дефиса)
`seasonvar-smotret-onlain-besplatno...` — **12 469**.
Зачем: SEO-прокладки под запрос, не отдельный рабочий сайт.

### 7. Глубина субдоменов ≥ 3
`a.b.c.example.tld` и глубже: **1 652**.
Зачем: почти никогда не «главный» рабочий домен, а технический хвост.

### 8. Разложить 1а по семействам бренда (корзины, не удаление)
Сейчас каша. Крупные куски: lordfilm **87 592**, vavada **45 473**, 1xbet **39 365**, lordserial **30 039**, casino* **28 712**, azino **11 397**, mostbet **11 882**, admiral **10 639**, rutor **7 852**.
Зачем: понять состав. Это не моральный фильтр, это нарезка «какой рабочий сервис».

### 9. Оставить только бренды с толстой фермой зеркал (≥ 50 алиасов)
Таких регистрируемых ферм **186** (`123rutor.su` 3239 алиасов, `piratbit.fun` 2939).
Зачем: если зеркал много, корень скорее живой и его копируют. Одиночки — слабее сигнал.

### 10. Наоборот: отдельно синлтоны
Домен встречается один раз: **216 193**.
Зачем: либо уникальный рабочий сайт, либо опечатка/мертвый хвост. Имеет смысл смотреть отдельно, не смешивать с фермами.

## 1б — репозитории / скилы / парсеры

### 11. Только полные GitHub-URL
Оставить `https://github.com/owner/repo`. Вынести **68** строк без `github.com`.
Зачем: без URL клонировать нечего. Имя скила ≠ рабочая ссылка.

### 12. Голые имена маркетплейса без репозитория
`youtube-summarize`, `clawhub1`, `solana-wallet-tracker` — **25** простых имён + опечатки clawhub.
Зачем: это ярлык из каталога, не объект. Работоспособность тут не проверить по ссылке.

### 13. Имя похоже на запускаемый инструмент
В строке есть `mcp` / `skill` / `parser` / `scrape` / `plugin` / `toolkit` / `bot` / `agent`.
Грубо: mcp 132, skill 227, scrape 45, parser 11, bot 233, agent 207.
Зачем: это то, что выглядит как скил/парсер, который можно запустить. Остальное — случайный софт в той же кампании.

### 14. Имя похоже на учебный/игрушечный проект
`course`, `tutorial`, `from-scratch`, `portfolio`, `calculator`, `flappy`, `todo`, `fundamentals`.
Мало строк (десятки), но в сэмпле они сильно шумят: `Love-Calculator`, `Asp.NetCore-Fundamentals`.
Зачем: код может существовать, но это не рабочий инструмент каталога, а домашка.

### 15. «Заводской» владелец: много цифр или очень длинное имя
Цифр ≥ 30% в нике: **1 717** владельцев. Длина ника ≥ 24: **391** (`Anatomic-universalquantifier643`).
Зачем: конвейер копий. Репозиторий часто всё равно качается — фильтр про происхождение объекта, не про мораль.

### 16. Владельцы с ≥ 3 репозиториями
Таких владельцев **61**, максимум 11 репо на человека.
Зачем: один завод = пачка почти одинаковых рабочих ZIP. Можно схлопнуть до владельца.

### 17. Одинаковое имя репозитория у разных владельцев
Один и тот же `claude-mem` / `databricks-mcp-server` с россыпи аккаунтов.
Зачем: это копии одного рабочего объекта. Для понимания состава достаточно одной строки на имя.

### 18. Неполный указатель `owner/repo` без https
Сейчас **43** таких (`heldinhow/speckit-coding-agent`, `YPYT1/All-skills`).
Зачем: ссылку можно дописать до GitHub, но это ещё не готовая рабочая URL.

### 19. Узкий срез «парсеры / качалки / суммаризаторы»
Только `parser|scrape|download|summar|grabber|tracker`.
Это как раз ваш сценарий «рабочее ПО для парсинга», без отсечения из‑за вредоносности.
Зачем: отделить парсеры от остального рабочего софта в той же пачке FakeGit.

### 20. Вынести 6 пересечений со списком 2
`1xbet-32396.top`, `lordfilmbbb.online`, `melbetofficial.in` и ещё 3 — они уже в `00-overlap-both.txt`.
Зачем: двойная метка «рабочий бренд + фишинговый фид». Для чистоты 1а их лучше смотреть отдельно, не удаляя из рабочих по морали.
